The loop, with its receipts

Seven steps move a change from an idea to the card on my profile. This page walks one real change through all seven. Every step links to the GitHub object that proves it. As of 2026-09-06.

Tap a step. Only one stays expanded.

  1. 01

    Issue with acceptance criteria

    twoseat #4 · 2026-09-01T00:16:29Z
    Receipt
    twoseat issue #4, "Policy engine and never-block degrade path", created 2026-09-01T00:16:29Z with four acceptance criteria, three days before the pull request that closed it.
    Elapsed
    start
    How it gets gamed
    Write the acceptance criteria after the code.
    What catches it
    The two timestamps, and a pull request body whose first line is "Closes #4". The pull request template puts Direction and acceptance above Implementation.
  2. 02

    Gated pull request: ci, gitleaks, ai-review

    twoseat #19 · 2026-09-03T23:31:53Z
    Receipt
    twoseat pull request #19, created 2026-09-03T23:31:53Z: three pushes, and on the last one, 6c2573f4, all three checks concluded success at 23:39:47Z. The review seat's reply on that push could not be read as a findings list, so its comment was rewritten at 23:39:44Z to say "The review did not run" and the check passed anyway. That is the rule this pull request introduced, working: the gate decides, and never enforces from inside itself. The retry is tracked in issue #15.
    Elapsed
    +2 d 23 h 15 min
    How it gets gamed
    A gate that always passes.
    What catches it
    The comment prints its own decision, and the dashboard lists every merged pull request whose decision read block or not-reviewed with no gate-bypass label: gate-bypass rate.
  3. 03

    Merge, by me

    8b659cc0 · 2026-09-04T04:40:29Z
    Receipt
    merge commit 8b659cc0, 2026-09-04T04:40:29Z, 15 files. Branch protection on main requires exactly two contexts, ci and gitleaks. The review check is deliberately not one of them, which is the same rule as step 02 applied to branch protection: a review seat that is wrong or unavailable can never block a merge.
    Elapsed
    +5 h 9 min
    How it gets gamed
    Skip the label.
    What catches it
    Unlabeled bypasses: pull requests whose latest twoseat comment decided block or not-reviewed, has no Decision row, or is missing, and that carry no gate-bypass label. Listed with links on the gate-bypass tile.
  4. 04

    Release with a Verified section

    twoseat v0.1.0 · 2026-09-04T18:07:16Z
    Receipt
    twoseat v0.1.0, published 2026-09-04T18:07:16Z. The notes end with a ## Verified heading followed by a link to the Actions run in step 05. Green CI is not a deploy.
    Elapsed
    +13 h 27 min
    How it gets gamed
    Paste a heading with any link. Cut trivial releases to inflate the count.
    What catches it
    flightdeck follows the link with one REST call and counts only a portfolio run that concluded success and was created after the release was published. Unverified releases are listed by name with the reason, in gray, never hidden: verified releases.

    What catches it
